Practical 2: Password Encryption and Decryption using RC4 (CrypTool)
Aim: Use CrypTool to encrypt a password with the RC4 algorithm, then decrypt it and verify that the original value comes back.

Tools needed: CrypTool 1 (CT1) for Windows (free), a screenshot tool (Snipping Tool / Win+Shift+S)
Sample data used here: Password (plaintext) = Admin@123    Key = 1A2B3C4D (hex)
(You can use any password and key of your choice.)

======================== STEPS TO PERFORM ========================

--- Part A: Installation ---

Step 1: Open your browser and go to the official CrypTool website:
        https://www.cryptool.org
        Go to the Download section and download CrypTool 1 (CT1) for Windows.

Step 2: Run the downloaded setup (.exe) file.
        Choose the language, click Next, accept the licence, keep the
        default folder and click Install, then Finish.
        --> Take a screenshot (Installation).

Step 3: Open CrypTool from the Start Menu.
        OUTPUT: The CrypTool main window opens with a blank document.

--- Part B: Encryption ---

Step 4: In the blank document, type the password you want to encrypt.
            Example:  Admin@123
        --> Take a screenshot (Plaintext).

Step 5: Click the menu:  Encrypt/Decrypt  ->  Symmetric (modern)  ->  RC4 ...

Step 6: A "Key entry" dialog box opens.
        Enter the key in hexadecimal.
            Example:  1A2B3C4D
        Click the Encrypt button.

Step 7: A new window opens with the encrypted text (ciphertext).
        OUTPUT: Unreadable output (shown as hex/characters) instead of Admin@123.
        --> Take a screenshot (Encryption).

--- Part C: Decryption ---

Step 8: Keep the encrypted window active (the one with the ciphertext).

Step 9: Click the menu:  Encrypt/Decrypt  ->  Symmetric (modern)  ->  RC4 ...

Step 10: Enter the SAME key that was used for encryption.
            Example:  1A2B3C4D
         Click the Decrypt button.

Step 11: A new window opens with the decrypted text.
         OUTPUT: Admin@123 (the original password).
         --> Take a screenshot (Decryption).

Step 12: Verify: compare the decrypted text with the original text.
         They are identical, so decryption is successful.
         (Optional: decrypt with a WRONG key and note that you get
         garbage text. This proves the key is what protects the data.)

Step 13: Paste all screenshots in your practical document under the
         headings: Installation, Encryption, Decryption.

======================== NOTES (THEORY) ======================

RC4 Algorithm
- RC4 is a STREAM cipher: it encrypts data one byte at a time.
- It is a SYMMETRIC algorithm: the same key is used for encryption and decryption.
- It uses a variable-length key (1 to 256 bytes, i.e. 40 to 2048 bits).
- The key creates a pseudorandom "key-stream". The key-stream is combined
  with the plaintext using XOR to produce the ciphertext.

Simple formula
- Encryption:  Ciphertext = Plaintext XOR Keystream
- Decryption:  Plaintext  = Ciphertext XOR Keystream
  (XORing with the same keystream twice gives back the original.)

Example (XOR on bits)
- Encryption:  10011000 XOR 01010000 = 11001000
- Decryption:  11001000 XOR 01010000 = 10011000  (original is back)
  XOR rule: same bits give 0, different bits give 1.

How RC4 works (2 phases)
1) Key Scheduling Algorithm (KSA) - prepares the state
   - Create a state array S with values 0 to 255 in order.
   - Create a temporary array T by repeating the key until it has 256 bytes.
   - Shuffle (permute) S using the values of T.
2) Key Generation / Stream Generation (PRGA) - makes the keystream
   - Pick one byte from S in a systematic way and shuffle S again.
   - Repeat for every byte of the message. Each byte is XORed with the plaintext.

Features of RC4
- Symmetric key algorithm (one key).
- Stream cipher (byte by byte).
- Variable key size.
- Fast and efficient, good for low-power devices.
- Widely used earlier in Wi-Fi (WEP), SSL, VPN and file encryption.
- Has vulnerabilities (bias in the first bytes of the keystream), so it is
  no longer recommended for new applications.

Advantages
- Very fast and efficient.
- Simple to implement in software or hardware.
- Flexible key size.
- Widely supported.

Disadvantages
- Known vulnerabilities (keystream bias) that can help recover the key.
- Weaker than modern ciphers like AES or ChaCha20.
- Maximum key length is limited (2048 bits).
- Not recommended for new applications.

Memory trick: RC4 = Fast + Simple + Same key + One byte at a time, but OLD and WEAK.

Stream cipher vs Block cipher (extra)
- Stream cipher (RC4): encrypts 1 byte/bit at a time.
- Block cipher (AES, DES): encrypts fixed-size blocks of data (e.g. 128 bits).

======================== IMPORTANT VIVA QUESTIONS ======================

1. What is RC4?
-> A symmetric stream cipher with a variable-length key that encrypts data one byte at a time using XOR.

2. What is a stream cipher?
-> A cipher that encrypts data bit by bit or byte by byte using a keystream.

3. What is a symmetric key algorithm?
-> One that uses the same key for both encryption and decryption.

4. What is the key size of RC4?
-> Variable, from 1 to 256 bytes (40 to 2048 bits).

5. What is a keystream?
-> A stream of pseudorandom bytes generated from the key, which is XORed with the plaintext.

6. How does RC4 encrypt and decrypt?
-> It XORs the plaintext with the keystream to encrypt, and XORs the ciphertext with the same keystream to decrypt.

7. What are the two phases of RC4?
-> Key Scheduling Algorithm (KSA) and Key Generation (stream generation).

8. What is the size of the state array S in RC4?
-> 256 bytes, S[0] to S[255].

9. What is the XOR operation?
-> A bit operation that gives 0 for equal bits and 1 for different bits.

10. What is CrypTool?
-> A free educational software used to learn and perform cryptographic operations like encryption, decryption and cryptanalysis.

11. Why is RC4 no longer recommended?
-> It has known weaknesses (such as bias in the first bytes of the keystream), so stronger algorithms like AES or ChaCha20 are preferred.

12. Name two advantages and two disadvantages of RC4.
-> Advantages: fast, simple to implement. Disadvantages: known vulnerabilities, weaker than AES.

13. What happens if the wrong key is used for decryption?
-> The output will be meaningless garbage text, not the original password.
