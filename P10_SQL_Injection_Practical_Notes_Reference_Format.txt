======================== NOTES (THEORY) ======================

SQL Injection
- SQL Injection (SQLi) is a web security vulnerability caused by
  improper handling of user input before it is used in SQL queries.
- It can allow an attacker to change the intended database query.

Working Principle
- A web application sends SQL queries to a database.
- If user input is directly added to the query without proper
  validation or parameterization, the input can change the query logic.
- This may allow authentication bypass or access to database information.

Types of SQL Injection
- In-band SQL Injection = injection and results use the same channel.
- Blind SQL Injection = information is inferred from application
  responses when database errors/results are not directly shown.
- Time-based Blind SQL Injection = time delays are used to infer results.
- Out-of-band SQL Injection = information is obtained through another
  communication channel such as DNS or HTTP.

Effects of SQL Injection
- Unauthorized access to confidential information.
- Bypassing authentication.
- Reading, modifying or deleting database records.
- Compromising application integrity.
- Loss of data confidentiality and availability.

Identifying SQL Injection Vulnerabilities
- User input is directly used in SQL queries.
- Database error messages reveal information.
- Input validation is weak or absent.
- Dynamic SQL queries are created by joining user input with SQL.

Prevention of SQL Injection
- Use parameterized queries / prepared statements.
- Validate and sanitize user input.
- Use stored procedures securely.
- Follow the principle of least privilege.
- Avoid displaying detailed database errors.
- Use Web Application Firewalls (WAF).
- Perform regular security testing and code reviews.
